# 教训

哪些错误已经烧掉过 GPU 时间、钱或者一整天的工作？每个错误留下了哪条规则？
这页按领域列出我这套环境里有日期的事故，每条一行。其他页面引用的理由都出自这里。

> **TL;DR**
> - 每行的格式：日期 — 发生了什么（代价）→ 规则。
> - 只保留有日期或有代价记录的事故。私有名称一律换成按用途起的名字（Box A、Box B 等）。
> - 大部分代价出自三个习惯：没跑 smoke test 就上批量、信报告不看产物、绕开闸机。
> - 新事故用 [templates/incident-rule.md](../../templates/incident-rule.md) 变成规则。

## 维护这一页的规则

1. **事故要有日期或实测代价才能进清单。**
   理由：没有日期的故事无法核对，每转述一次就走样一次。
2. **每条事故都写明它催生的规则，以及这条规则现在放在哪。**
   理由：只存在于聊天里的教训，会话记录一清理就没了。
3. **规则的理由留在拥有这条规则的文件里；changelog 只记一行。**
   理由：策略文件靠「丢理由、留约束」来精简（长期规则）。
4. **同一任务连败两次，agent 回去盘点工具，不做第三次尝试。**
   理由：常见原因是缺工具或没读文档，不是代码写错（策略条目 2026-08-27）。

机器名：Controller（跑 agent 的笔记本）、Box A（主力渲染机，同时是游戏机）、Box B（工作机）。
见 [02-environment.md](02-environment.md)。

## 真实案例

### 渲染与 GPU 时间

- 2026-06-25 — 一张 txt2img 图带着 denoise 0.5 提交，得出了「VAE 发灰」之类的假结论（一轮调查建在错误前提上）→ 下结论前先读实际提交的那张图。
- 2026-07-18 — 一个很难画对的服装概念试了 72 次 → 别和模型的先验硬拼；放弃这个概念或者换工具。
- 2026-07-20 — 计划任务重复触发，一次起了九个；VRAM 耗尽，训练卡在第 3 步 → 确认启动后立刻删掉任务定义；收尾时按前缀查一遍任务。
- 2026-09-01 — 通过 ComfyUI 的 `/free` 做全量内存释放，在拆 RAM 缓存时把 Box A 卡死 → free 只卸模型，统一走一个函数，释放后回读机器状态。
- 2026-09-03 — 看到「VRAM 只用了 40%」就关掉 gradient checkpointing；训练冲到 16,380 MiB 里的 15,899，速度慢了 9 倍 → 开着 checkpointing 的峰值预测不了关掉之后的峰值。
- 2026-09-16 — 用质量栈探画风（每张 3.5 分钟），停队只杀了叶子进程，一个子 shell 又多渲了 5 张，同 seed 覆盖毁掉 48 张里的 30 张（约 40 分钟 GPU、15 分钟重跑、排期拖后约 1 小时）→ 先渲 1 张 smoke，按这一步要验什么选引擎，每张落盘即隔离，停队杀整个进程组。
- 2026-09-16 — 一次性测试图一直在挤两台机器的磁盘（光一次黑图调试就在两边留了 20 多张）→ 任务收尾时清掉测试图；2026-10-06 加严为默认删除，留教训，不留图。
- 2026-09-17 — 28 块的 LoRA 没做重映射就挂到 52 块的 Anima 底模上，出图是乱涂且不报错；机器上 166 个 Anima LoRA 没有一个是原生 52 块 → 挂载前先重映射块索引。
- 2026-09-18 — 在部分加载的 INT8 ConvRot checkpoint 上挂 LoRA，6 次全崩，漏掉约 11 GB VRAM，`/free` 收不回来 → 只有重启服务能释放；这种格式不挂 LoRA。
- 2026-09-22 — 「每次出图后释放 VRAM」让连续出图的每一张都重载 checkpoint 和 LoRA；每次释放要 1.9 秒往返 → 用租约加空闲回收器代替逐张释放。
- 2026-09-30 — 复用本地缓存的输出路径，拿回的是另一张图的像素配上新元数据 → 按 prompt 查历史；去掉本地缓存路径复用。
- 2026-09-30 — 在 ComfyUI 0.27.1 上原样重跑，一直轮询到 1,800 秒超时，看起来像卡死 → 在历史里查同一个 prompt，直接取已有文件；404 就立刻失败。
- 2026-10-01 — 一个长时间多 agent 会话之后，img2img 出黑图；重启就好了，原因没抓到 → 出黑图先重启机器，再去查精度。

### 远程 Windows 机

- 2026-06-21 — Box B 上一次训练崩溃后留下一个占着 16 GB 以上内存的僵尸 Python → 重试之间先列出 Python 进程，确认命令行是训练器（不是 ComfyUI），再杀这些 PID。
- 2026-07-02 — ComfyUI 的「重启」其实什么都没重启 → 先杀掉占着监听端口的进程，再启动。
- 2026-07-16 — 通过 SSH 找窗口失败，被理解成「桌面不能用」；SSH 会话本来就看不到控制台桌面 → 用调试协议驱动桌面应用，不靠 SSH 截图。
- 2026-08-25 — 13 个孤儿多进程 Python 占着 33 GB，用一条误导性的存储报错挡住了一套验证过的配置 → 按监听端口或命令行杀进程，并核对监听者身份，不只看「端口活着」。
- 2026-09-01 — PCIe 链路读到 Gen3、BAR 只有 256 MiB，被诊断成 BIOS 故障；重启一次就回到 Gen5 x16 → 怪硬件之前先重启、重测。
- 2026-10-01 — 某台机器上 60 KB 及以上的远程 PowerShell 载荷会间歇卡住（1–46 KB 从没卡过）→ 大文件先拷过去，再发一个小的执行脚本。
- 2026-10-13 — 某台机器上加载 CIM 模块卡死，留下孤儿进程，最后连 SSH banner 都握不上（三周 14 次超时）→ 这台机器只用纯 cmd 命令或一次进程创建调用；不要拉长超时。
- 2026-10-13 — 第二跳 SSH 丢了引号，弄坏了一个 docker 命令模板 → 每过一跳加一层引号；超过三层就改发脚本文件。
- 2026-10-13 — 通过 SSH 建的计划任务只在有人登录时才跑 → 任务 XML 用带 BOM 的 UTF-16 导入，登录方式选 S4U。
- 2026-10-13 — 在非交互 SSH 会话里「移到回收站」其实是永久删除 → 文件移到同盘、带日期的隔离文件夹，并留恢复映射。
- 2026-10-19 前 — agent 的 Bash 工具会把 `>nul` 改写成 `>/dev/null`，在 Windows 上这是个不存在的路径 → cmd 文件用文件工具写、用 CRLF；单行命令用 `>NUL:`。
- 2026-10-19 — Box B 的代理指向一个没人监听的本地端口，依赖安装失败 → 告诉主人；绝不改作业环境里的代理变量。

### agent 与派发

- 2026-06-20 前 — 让一个无头编程 agent 出图，它写代码画了一堆多边形 → 要求用原生图像工具，工具缺失时必须输出约定的退出标记。
- 2026-07 — 两个同家族评审放过了一个纯测试 PR；另一个工具找出 6 处宽松断言（下一个 PR 又找出 3 处）→ 每个测试 PR 都由另一家工具从变异测试的角度评审。
- 2026-07 — 隔离检查只打印了解析出的根目录，而一份拷贝来的配置让受限子树把产物写进了主输出树；两个同家族 agent 都没发现 → 隔离测试要断言路径落在自己的子树里；评审换一个工具家族。
- 2026-07-05 — 某个 agent CLI 的孤儿 worker 进程连跑几天，合计约 700% CPU，把 Controller 烤热了 → 父进程是 PID 1、连转几天的孤儿可以放心杀。
- 2026-08-04 — 从沙箱里的会话 shell 直接启动 worker CLI，嵌套沙箱报 exit 71 → 外部 worker 只通过终端复用器服务启动。
- 2026-08-14 — 一个 worker 调了一次 advisor，读两节文本找冗余，花了 7.7 分钟、10.2 万 token → worker 永远不调 advisor，也不再往下派。
- 2026-09-20 — 给运行中的 worker 排队发的修正一直没送到，白下了约 4 GB → 改完指令之后，去看 worker 实际的文件活动。
- 2026-10-08 — 4 条 Haiku 调研线里有 3 条跑偏 → 调研线交给 Sonnet。
- 2026-10-15 — 一个文献复查 Workflow 让所有 agent 都跑最强模型，烧掉了额度 → Workflow 里每个 agent 调用都写明一个便宜的模型。
- 2026-10-19 — 一个 Haiku subagent 连续三次只抄了约 20,000 个 base64 字符里的 1,643 个 → 由 root 分块推送，逐块核对哈希。

### 会话与上下文

- 2026-07-04 — 沙箱里的 git 视图漂了（同一个 commit 两个哈希，删除写穿了，提交没写穿）→ 第 0 步把 status、worktree 列表和 HEAD 各跑两遍对比；对不上就停，写交接。
- 2026-08-25 — 回复又变长，查下来是长会话里的指令稀释，不是模型变了 → 加一个重注入 hook，助手回合满 12 次才触发。
- 2026-09-16 — 一个有 55 个脏文件的主检出被当成孤儿工作，打了 WIP commit 并切走；其实它属于一个活着的会话 → 动共享检出之前，先列出活会话和会话记录的修改时间。
- 2026-09-17 — 一份云端写的交接误诊了到渲染机的链路，还建议覆盖那个自动选路的启动定义 → 照交接的诊断动手之前，先读真实的服务定义。
- 2026-10-13 — 接手会话找不到文件，因为交接里漏了工作目录和分支 → 这两项在交接和任务库备注里都是必填。
- 2026-10-14 — 接手会话的触发器从没触发过：70% 按 1M 窗口算，而压缩在 500k 窗口下发生（约 467k 时触发）→ 阈值按实际生效的压缩窗口算。
- 2026-10-14 — 一个任务停在「进行中，等主人回复」，收尾时待办清单是空的 → 等人的任务一律设成 blocked。

### 网络与闸机

- 2026-08-06 — 收紧为只认受管 hook 后，四个用户 hook 静默失效（2026-09-15 救回两个，另外两个一直没恢复）→ hook 只放在受管目录。
- 2026-08-20 — heredoc 里只是出现了 wrapper 的名字就撞上闸机 → 写文件用文件工具；其他命令里不提 wrapper 名字。
- 2026-08-28 — 传了机器别名而不是解析好的 URL，生成假主机名并收到 403；白派了一个网络专员 → HTTP 辅助工具只收解析好的完整 URL。
- 2026-09-10 — 一个被闸机拒绝的 GitHub 子命令，30 天里在 63 个会话中被试了 244 次，都是照文档示例抄的 → 这个子命令一律拒绝，示例全部改写。
- 2026-09-16 — 一个 agent 看到守卫就宣布公开 API 调不通，把一条能跑的命令交给了主人 → 先发一个最小请求，看真实报错。
- 2026-09-22 — 笔记本拿到了另一个网段的地址，局域网链路静默退到了慢速的远程通道 → 先从路由缓存诊断，不要先怪代理规则。
- 2026-09-29 — 经受管代理上传 1.5 MB，一直挂到超时 → 清掉 `Expect: 100-continue`。
- 2026-10 — 三周里约 250 次闸机拒绝，都来自串联、管道或加前缀的 wrapper 调用 → 一次 shell 调用只跑一条 wrapper 命令，前后都不加东西。
- 2026-10-19 — 一份带 API key 的 SSH 会话环境差点被存进作业队列的状态文件 → 作业环境按变量白名单构造。
- 2026-10-19 — 一个 post-tool hook 改写了远程输出，脚本看起来没跑 → 当作 hook 输出缺陷处理；改一次形状，然后把命令交给主人。

### git 与 CI

- 2026-07 — 合并前留了三条评审意见没处理，多花了一个 PR → 每条评审意见合并前都要有处置。
- 2026-08-08 — 生产图库服务从 worktree 启动，索引从几百张掉到个位数 → 生产服务只从主检出启动，脚本里加守卫。
- 2026-08-13 — 一个「早就存在」的缺口在新代码下改变了严重程度，弄坏了 22 张方向卡里的 7 张 → 按当前 tip 的行为判定缺陷。
- 2026-08-13 — 8 次 CI 红灯分成四类（守卫杀了安装、脚本没登记、状态文件体积上限、TLS 重置）→ 重跑前先给第一条报错分类；绝不靠调高上限来变绿。
- 2026-08-16 — 托管 CI 的月度额度用完 → 按成本分 lane：PR 只跑短任务，重 lane 每周跑和手动触发，本地 runner 镜像托管侧的选择逻辑。
- 2026-08-16 — 一个 worktree 里藏着一整条没进过任何分支的功能（16 个已跟踪文件、10 个测试），另一个 worktree 里有 255 MB 产物，主检出里没有副本 → 删任何 worktree 前，先扫描并 rsync 回未跟踪的工作。
- 2026-08-23 — 评审在仓库根目录跑递归 grep，跑了 11 分钟以上，吃光了超时 → 只用 `git grep` 或限定范围的搜索。
- 2026-09-16 — 一份评审结论笔记被提交进了被评审的 diff，下一轮评审把它当注入拦下 → 结论只写在 PR 评论里。
- 2026-09-16 — 同一个 PR 上的第三轮评审浪费了时间 → 最多两轮；之后的建议走后续 PR。
- 2026-10-06 — 一条 28 个 commit 的分支从没开过 PR，却被当成已合并，生产上一个接口回 404 → 认定已合并之前，先 `git log origin/main` 查这个文件。
- 2026-10-14 — 一次大 push 在 sideband 断开后仍报成功 → 每次 push 都用 fetch 加 `rev-parse` 核对。

### 云端花费

- 2026-08-25 — Civitai 的公开图片接口不再返回生成元数据（10 次全空）→ 别假设 REST 会给元数据；改用解析页面的导入路线。
- 2026-08-25 — NovelAI 的边缘节点对默认的 Python User-Agent 回 403/1010 → 永远带自定义 User-Agent。
- 2026-09-05 — 回复里贴了两条付费探针命令，同时又在收件箱里被批准；19 张图渲了两遍（257 Buzz）→ 先查账本和输出目录，默认 resume，事后对数。
- 2026-09-30 — NovelAI 的费用估算偏低，账本还把免费图记成了付费 → 用网站自己的公式和像素规则。
- 2026-10-19 — 一条超过 1,031 个字符的 Midjourney 提示词被静默改写、丢了词 → 提示词正文控制在约 1,000 个字符以内。

### 评估与评审

- 2026-07-02 — 手工转述的方向意图漏了一个槽位，评审因此选错了赢家 → 评审意图从卡片机械生成。
- 2026-07-03 — 结构塌掉的图零标记通过了 QC 闸门 → 不因为闸门通过就跳过视觉初筛和终审。
- 2026-07-16 — 一个外部评审和机械层都没通过数手指脚趾的校准 → 它们的结论只作辅助，永不计入评分。
- 2026-07-17 — 看缩略图得出了一个假的「细节差异」结论 → 看对比图之前先做像素级 diff。
- 2026-08-04 — 叠两个画风 LoRA 把脸弄崩，自动闸门 10 次全没发现 → 单变量消融，然后移除元凶并加回归测试。
- 2026-08-27 — 裁切切掉了一排脚趾，报了个假成功；是人看出来的 → 四边包围检查，加人工终审。
- 2026-08-27 和 2026-09-17 — 用 500 帖的门槛筛画师候选，把想要的商业插画师全筛掉了（他们只有 164 到 490 帖），同一个错犯了两次 → 看商业履历，不看帖数。
- 2026-09-05 — 一个晚上逐张打分，同一个场景判了 58 次 → 客观缺陷由 agent 判；只有口味题交给人，而且小批量。
- 2026-09-15 — 一个 24 格的裸模型矩阵浪费了人的注意力 → 新模型每个出 1 张，然后问要挂哪些 LoRA。
- 2026-09-30 — 一条记录在案的 3.8 秒热启动耗时，重测是 2.1 秒 → 在生产服务上重测，丢掉冷启动数据，删掉过期数字。
- 2026-10-01 — 被归咎于新底模的瑕疵，其实来自两个强画风 LoRA 叠加（同 seed 剂量测试和逐个剔除测试查出）→ 评判模型之前先隔离画风栈。

## 试过又放弃的

- **每次出图后释放 VRAM。** 换成租约加空闲回收器（2026-09-22）。
- **远程机卡住就拉长超时。** 换成更窄的命令形状（2026-10-13）。
- **只用同家族评审。** 2026 年 7 月两次漏检后放弃；改由另一个工具家族评审。
- **写轮询脚本等 CI。** 放弃：查一次，等，再查一次（长期规则）。
