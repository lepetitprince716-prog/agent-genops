# 理念

[English](../en/00-philosophy.md) | 中文

这页写的是整个仓库的工作原则。每条原则都来自一次实测、一次事故或一个长期决定，理由就写在规则旁边。后面的页面如果和这里冲突，以这里为准，并回头修那一页。

> **TL;DR**
> - agent 负责规划、派工、验收和记录；ComfyUI 和云服务只负责出图。
> - 真相是正在运行的机器和落在磁盘上的产物。文档、退出码、worker 的自述都只是说法。
> - GPU 时间、付费额度和人的注意力是最稀缺的三样东西。
> - 机器负责淘汰，审美由人来定。
> - 写清哪些是实测、哪些是假设、哪些还没核实。教训留下，测试图删掉。

## 一、工作放在哪里

1. **agent 平台是控制面，后端只出图。**
   理由：所有入口（网页、聊天、MCP 工具、命令行）走同一条执行链，配方和资源规则不会因为换了前端就分叉。读取 ComfyUI 画布的工具可以查看、修改用户打开的图，但从不替人排队出图。在画布里设计工作流，等于把方法放在了 agent 没法测试、对比、审查的地方。

2. **每个事实只有一个权威来源，入口保持很薄。**
   理由：同一份内容抄两遍就会走样。仓库级的 agent 说明只写阅读顺序和边界；每个领域有一份权威文件；配方只登记一次，调用方只写名字；脚本有登记表，agent 动手前先查有没有现成的，CI 会拒绝没登记的新脚本。

3. **默认只出计划，执行要明确说。**
   理由：路由脚本默认只打印命令或计划，加 `--run` 才真跑。动用 GPU 之前先过一道只读的 HOLD 检查（服务可达、节点和模型文件在线、队列空闲），状态未知按忙处理。做计划、看预览、准备任务包，都不等于获准出图。

4. **不同后端各自做适配，不硬合并。**
   理由：本地 Anima、NovelAI、Midjourney、视频模型的提示词写法、运行环境、成本和产物形态都不一样。曾经有人提议做一个通用规划器统一它们，被否了；抽象要等出现第二个真实用例再做。

## 二、真相与证据

5. **在线机器的实况压过任何文档。**
   理由：判断一台机器活没活，查它的队列接口，不用 ping（ICMP 被防火墙挡着；system-stats 接口还出现过队列正常却返回 500 的情况）。checkpoint 的名字以在线服务为准，本地索引常常落后一代。几条「VAE 发灰」的结论，最后查出是 denoise 参数传错了；解决办法是去读真正提交上去的那张图，而不是源码里的默认值。

6. **产物才是证据，退出码不是。**
   理由：计划、已排队、已生成、质检通过、人工选中、正式发布，是六个不同的状态。2026-08-23 有一次，派发回执显示成功，上游其实根本没收到请求。验收要打开文件看。

7. **写清哪些是实测、哪些是假设、哪些没核实。**
   理由：测量结果换个模型就不一定成立。同一种注意力加速在一个模型上快了 1.30 倍，换到另一个模型只剩 5–7%。社区流传的提示词规则，好几条被我们自己的测试推翻了。提示词效果按「N 个种子里几次命中」报告，没测过的想法标成假设。

8. **机器负责淘汰，审美由人判断。**
   理由：有一张脸型崩掉的图，所有自动关卡都放行了（身份分 10/10，质检零告警），只有人眼看出来。标量美学分把平庸的基线图排在有艺术感的候选前面。agent 曾经认为 8 步采样够用，人的底线是 16 步，所有回本测算因此翻了一倍。客观缺陷由 agent 判；评审 agent 只排序，不拍板。

## 三、稀缺资源

9. **三张以上的批次，先出一张 smoke。**
   理由：2026-09-16 一轮探针犯了三个本可避免的错，白占约 40 分钟 GPU，排期往后推了约一小时。smoke 要核对三件事：单张耗时、文件落在哪、文件名会不会互相覆盖。

10. **按这一步要验证什么来选引擎。**
    理由：探画风、探构图只需要单遍底图，几十秒一张；放大加 detailer 的质量栈要几分钟一张，只留给成品。

11. **渲染机是别人的电脑。**
    理由：主渲染机也是仓库主人的游戏电脑。路由先探主机，主机忙或正在游戏时才转到第二台。可能有人在玩游戏时，不做 4 倍模型放大，因为共享显卡会爆显存。

12. **预算是闸门，出错就拒绝；上限不是目标。**
    理由：Civitai 付费出图先拿免费报价，单次超过 30 Buzz 或当天超过 150 Buzz 就停，每张图记一行账。2026-09-05 有一条付费命令被重复执行，浪费了 257 Buzz。有个方案提议把上限设到 2000 Buzz，最后砍到了 500。云端一轮出多少张，按「下结论需要几张」来定。

13. **先测量再调优，先动最大的那根杠杆。**
    理由：同一个配方换种子，耗时能差 24%，所以单样本 A/B 分辨不出 20% 以内的差别。每个开关都要有明确的「关」组。同一个注意力内核，在换量化之前只值 5–7%，换完之后值 14–21%。

## 四、agent 与派工

14. **派工只为两件事：并行展开，或者保护主会话的上下文。不凭习惯派。**
    理由：一条线做到底的活，同一个模型降低 effort 自己做，比加一个 worker 效果更好。每份活交给「失败了主会话还兜得住」的最低档模型。2026-10-08 四条 Haiku 调研线有三条跑偏，之后调研一律交给 Sonnet。

15. **worker 的自述不算验收。**
    理由：主会话要亲自重跑数字、读结果文件，还要看 worker 实际写了什么文件。2026-09-20 有三条纠正指令排在忙碌的 worker 后面，一条都没送到，白下了约 4 GB 的东西。

16. **先调研再动手；连续失败两次就回去重新盘点。**
    理由：反复失败通常是缺了工具或没读文档，不是代码写错。手写实现排在最后，前面先查现成的 CLI、库和开源项目。

17. **不绕过任何闸门。被拦住时，交出一条能直接运行的命令。**
    理由：被拒绝的调用根本没有执行。agent 可以把命令形态改一次；还不行，就给仓库主人一条幂等的命令：会备份它要覆盖的文件，先在副本上试过，并写明哪部分没验证。

## 五、记忆与诚实

18. **记忆是带日期的快照，不是事实。**
    理由：笔记会过期。在 ComfyUI 0.33 上记下的结论，升到 0.42 后没有重新核过。每条状态笔记都带日期，用之前先对照 git 或在线机器。记忆文件一个文件只写一件事，定期查重复和断链。

19. **教训留下，测试图删掉。**
    理由：一次性的测试图把两边的磁盘都塞满过。测试图默认删除，要保留得给出理由。Windows 上通过 SSH 调用「移到回收站」，实测是永久删除（2026-10-13），所以改成移到同一块盘上带日期的回收文件夹，由人来清空。

20. **质量优先；「全部」就是全部。**
    理由：仓库主人的决定。视觉验收要覆盖每一个单元，不抽样。

21. **结论先行，坏消息一个字都不删。**
    理由：长报告没人读完，所以篇幅是硬限制。要压缩时先删解释；失败、数字和原样命令必须留着。

## 六、创作

22. **先有概念，再写提示词。**
    理由：如果说不清这张图要让看的人感受到什么，就还没到出图的时候。

23. **不迁就模型去改审美。**
    理由：模型做不到的地方，记成这个模型的扣分项，不去改场景来凑它的长处。

24. **不信任图像模型画出来的字。**
    理由：生成的文字一直是老毛病。图里不放字，文字事后用代码或专门的模型加。

## 规则是怎么变过来的

上面是当前版本。下面几次大改，以及逼出这些改动的原因。

| 以前 | 现在 | 起因 |
|---|---|---|
| 每次付费出图都要确认 | 常设预算：先报价、有上限、记账、带断点续跑参数 | 2026-09-30 的决定；平台对 API key 没有服务端上限，只能客户端自己管 |
| 每张图渲完都 `POST /free` | 路由按租约占用显存，空闲后由回收器释放 | 每次 free 要 1.9 秒往返，还会把已加载的权重踢出去 |
| 每个 agent 各注册三个 MCP 服务 | 一个所有 agent 都能用的 MCP 服务 | 分别注册一直没人配，工具成了摆设（2026-09-16） |
| 逐张打分 | 每轮一批 triage；需要拍板的事进收件箱 | 有一晚同一个场景被评了 58 次（2026-09-05） |
| 裸模对比矩阵 | 新模型只出一张，挂上平时用的 LoRA 栈 | 24 格裸模矩阵没给出任何有用信息（2026-09-15） |
| 默认一个 worker 模型 | 分档：Haiku 到 Opus high，外加给已定设计用的 Sonnet max | Haiku 做调研会跑偏；规则改成「失败了主会话兜得住的最低档」 |
| 每个小改动开一个 PR | 本地先提交，攒一个阶段再推送和审查 | 每个小 PR 要五六次网络调用外加一轮审查（2026-09-01） |

## 护栏，以及谁在执行

| 护栏 | 执行方式 |
|---|---|
| 动 GPU 前先过 HOLD | 路由探针；机器忙或状态未知时以非零码退出 |
| 三张以上的批次先出 smoke | 写在 runbook 里；smoke 三项都过了才放整批 |
| 付费出图不超预算 | 客户端闸门，出错即拒绝；每轮结束后对账 |
| worker 不能再派工，也不能调 advisor | 每个 subagent 定义里共用的页脚规则 |
| 作业环境里不带密钥 | 作业运行器只传白名单里的环境变量 |
| 这个仓库里没有私人信息 | `tools/privacy_scan.py`，挂在 git hook 和 CI 上 |
| 每个事实只有一个权威来源 | 私有工作室仓库里的脚本登记表和 CI 棘轮检查 |
