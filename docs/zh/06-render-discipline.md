# 出图纪律

agent 在共享 GPU 机上跑一批图，怎样才不白烧 GPU、不把自己的结果覆盖掉、不留一地垃圾。
这页讲 smoke test、引擎选择、落盘隔离、队列控制、给机主让机、显存释放、清理和交付。

> **TL;DR**
> - 3 张及以上的批次，先用同一条命令渲 1 张 smoke，核对单张耗时、落盘路径和文件名会不会撞。预计超过 30 分钟的批次，开跑前先报。
> - 按「这步要验什么」选引擎：探方向用底图单遍，质量栈只给成品。
> - 每张图各自落盘。停队按进程组杀，杀完要证明整棵树没了。
> - 派工前先探机，机主要用就让。显存走租约，由空闲回收器释放，不再每张都 free。
> - 测试图默认两边都删。Windows 机移进同盘带日期的回收目录，绝不用回收站。结果走画廊页，不往对话里贴。

GPU 时间是排期的硬约束，一个批次跑废，整条线就往后推。下面大部分规矩出自 2026-09-16 那一轮探针，
见「真实案例」。

## 规则

### 开跑之前

1. **3 张及以上的批次，先用一模一样的批量命令渲 1 张 smoke。**
   理由：2026-09-16 的画风探针轮没做 smoke，一次犯了三个错（引擎选错、停队只杀叶子进程、同 seed
   覆盖）。Box A 白占约 40 分钟，补跑又是 15 分钟，排期拖后约 1 小时。smoke 要核对三件事：单张耗时；
   图和结果 JSON 落在哪、后处理会不会再写一份；批次里两张图会不会拿到同一个文件名。
2. **smoke 耗时乘以张数，把总时长写进单据；超过 30 分钟的批次开跑前先报。**
   理由：那一轮要是先算一下，3.5 分钟一张乘几十张，开跑前就能看出不对。30 分钟这条线是那次事故定下的。
3. **按这步要验什么来选引擎。**
   理由：探画风、构图、姿势只要底图单遍，几十秒一张（Anima 快线在 Box A 上热跑约 2.1 到 2.5 秒）。
   质量栈（放大加 detailer）是分钟级：Box A 上 SDXL 质量线中位数约 100 秒，Box B 上 Anima 满配
   84 到 108 秒。2026-09-16 恰恰拿质量栈去探画风，3.5 分钟一张。放大和 detailer 配方的现状看项目状态文件，
   别默认它是最新的。
4. **在共享机上做同 seed 对比之前，先清掉进程里残留的状态。**
   理由：2026-10-01 一个 IP-Adapter 节点原地改了模型的 block，普通的显存释放清不掉；同 seed 出图的平均像素差
   一直是 16.55，直到做了一次完整的内存释放。那天因此判错了两次。同一天长时间多 agent 会话之后出黑图，
   也只有重启机器才好。
5. **Box B 上的测试图不用逐批请示；Box A、网络、删除非测试数据仍要先问。**
   理由：2026-09-30 我把测试出图整体交给 agent，好让 Box B 跑满。这项常设授权的批次上限是 15 张，
   照样先 smoke、两边清理。

### 隔离

6. **每张图一落地就搬到它自己的位置，搬完再渲下一张。**
   理由：引擎按自己的规则起文件名。复用仓库里现成的隔离件（`--keep-into DIR` 这类参数，把 PNG 和
   元数据 JSON 成组搬走，重名加 `__vN` 后缀），命令写成 `render && keep`。不要再造一个。
7. **除非引擎能证明文件名唯一，否则一律当作会撞。**
   理由：有个生成器按「LoRA 名加 seed」命名。2026-09-16 五个纯 prompt 的档共用 seed，互相覆盖，
   48 张里废了 30 张。另一个引擎早就会自动加后缀，那次探针没用上。
8. **每次运行写进一个新的空目录，目录非空就拒绝。**
   理由：轮次绝不能混。app 的作业还会写一份本次产出的清单，从不扫整个输出树，并行的几次运行就不会互相认领对方的图。
9. **两条队列不能指向同一个结果目录。**
   理由：来自 2026-09-16 的批量渲染规则，常设。

### 队列和进程

10. **停队按进程组杀（`kill -- -<PGID>`，或先递归杀子进程再杀 runner），杀完列一遍进程，证明整棵树都没了。**
    理由：2026-09-16 杀了 runner 和引擎，可中间那个跑命令文件的子 shell 还活着，握着已经删掉的旧命令文件又渲了 5 张。
11. **先停队，再改计划；新计划写好了才重启。**
    理由：同一次事故。队列还在跑就改计划，等于两份计划同时在跑。
12. **Windows 机上的长任务用 WMI 创建进程来起；一次性计划任务确认启动后马上删掉定义。**
    理由：SSH 会话里起的进程会跟着会话一起死，Start-Process 没有窗口站时静默失败。2026-07-20 九个一次性计划任务
    同时重新触发，显存被吃光，训练卡死在第 3 步。收尾时按任务名前缀查，结果必须为空。
13. **排队中的 prompt 超时，按确切 id 删掉并确认已不在队里；正在跑的那个别碰。**
    理由：ComfyUI 对正在跑的 prompt 只有整机中断，会顺手杀掉别人的作业。瑕疵探针遇到这种超时会把队列归属标成不安全，然后中止。

### 机器是机主的

14. **派工前先探机；探针返回 HOLD（退出码 3）就不派。**
    理由：Box A 是我的游戏机。我这套环境里有个意图路由叫 `gen.py`，接受 `--box auto --probe`，每次 `--run`
    还会再探一次。`--box auto` 先扫 Box A，它忙（空闲显存低、队列非空、连不上）才转 Box B。这条取代了
    2026-07-18 那条「一律先走 Box B」。
15. **我自己在 Box A 上跑东西时，排队器要连续三次探到空闲才起跑。**
    理由：仓库主人的决定。我两个作业之间那一下空闲，不等于机器空了。
16. **我可能在打游戏时，不做模型放大（4x 那类），改用更高的原生分辨率一遍出。**
    理由：ESRGAN 一类 4x 放大的中间大图会把共享的 16 GB 显卡挤爆。桌面程序抢显存还让 Box A 的驱动静默崩过，
    预留显存因此提到 2.5 GB。
17. **判断机器活没活，看队列接口，不看 ping。**
    理由：两台机都按设计屏蔽了 ICMP；ComfyUI 挂了 SSH 照样在。system-stats 接口有一次返回 500，
    而 queue、prompt、object-info 都是 200。

### 显存

18. **跑完给显存上租约，由空闲回收器去释放；不要每张图都 free。**
    理由：每张都释放，连发的时候每张都要重新加载 checkpoint 和 LoRA，每次 free 还要付 1.9 秒远程往返。
    2026-09-17 起，跑完盖一个租约；一个脱离的回收器只在空闲满 300 秒、队列可读且为空时才释放（最长等 3600 秒），
    每台机一把锁只跑一个回收器，释放后再读一次机器状态确认。真要立刻还卡，有参数可以马上释放。旧规矩
    「每次跑完 POST /free」（2026-06-27 起的常规操作）已作废，2026-09-22 我确认模型常驻。
19. **只有换模型或我不用这台机了才完全卸载，用一条写明机器和模式的命令。**
    理由：2026-09-01 在 ComfyUI 0.33.1 上做完整内存释放把 Box A 卡死了，默认释放于是改成「只卸模型」。
    2026-10-19 在 Box B 上复测：这个模式在 0.42.1 上还留 1.43 GB（0.27.1 上留 2.1 到 3.3 GB）；完整模式 1 秒内全还，
    两个版本都没卡死。默认值改不改由我定，前提是先在 Box A 的 0.42.1 上测一次完整模式。
20. **任何空闲阈值都要算上常驻模型。**
    理由：模型常驻后，Qwen sidecar 的空闲显存只剩 45% 左右，40% 的阈值把空闲机误判成忙；那个 sidecar 的兜底阈值后来降到 35%。

### 清理

21. **测试图默认删，要留得我明说。**
    理由：两台机的磁盘都快满了，光一次黑图排查就在控制机和 Box A 上各留了二十多张废图。2026-10-06 收紧：
    每轮判完就清上一轮，不等任务收尾；对比图、拼图也算测试图；把经验写进单据的 findings，图不留。
    我点名当参照的单张可以留，回复里要写明留了哪张、在哪。
22. **两边都清，动手前先列出要清的东西和占用。**
    理由：渲出来的图常常有两份，一份在控制机，一份在机器的 ComfyUI 目录里。机器上要看 `output`、
    `input`（基准测试的输入图）和 `temp`（预览落盘）。
23. **Windows 机上绝不用回收站；移进同盘、带日期的回收目录，并写一份还原清单。**
    理由：2026-10-13 实测，经非交互 SSH 会话调用「送回收站」就是永久删除。回收目录保留原来的相对路径，
    还原清单记下每一次移动，回收目录由我自己删。控制机这边用系统废纸篓。
24. **远端一时清不了，就把残留写进单据目录里的 CLEANUP 文件。**
    理由：仓库主人的决定。收尾时连同单据一起清。
25. **只清出图子目录；数据集、训练 checkpoint、转换后的 LoRA、模型文件一律不碰。**
    理由：常设边界。训练验证图只留最好的几张（选优 epoch 的 A/B 对），放进仓库的分析目录（2026-07-20）。
26. **挑远端文件按文件名区间，或按机器自己算的时长，不按控制机的钟点。**
    理由：Box A 的系统时钟比控制机快 12 小时（2026-10-06）。

### 交付

27. **图和视频以画廊页链接交付，绝不加载进对话。**
    理由：媒体放进上下文很贵，compaction 一来就没了，视频在对话记录里也没法拖进度。一张 2048x3072 的原图 PNG，
    占的上下文约是缩小版 WebP 的 60 倍。之前试过的路都不通：发文件工具只显示一个文件卡片，base64 塞进小部件
    超过 512 KB 上限（2026-06-24/25）。我自己读图检查不受这条限制。
28. **一轮评审就是一个登记好的批次；批次登记后不可改。**
    理由：2026-09-05 一晚上逐张判，同一个场景判了 58 次。文件变了就不再提供，重新登记一个批次。默认用只看的网格，
    只有下一步取决于挑选结果时才开逐张判的模式。
29. **画廊服务只从主仓检出启动，批次也从主仓登记。**
    理由：2026-08-08 从 worktree 重启了服务，图库根指到一棵稀疏的树，条目数从几百掉到个位数。现在服务会拒绝 worktree 路径。

## 流程：在共享机上跑一批

1. 写单据：意图、机器、张数、seed、模型、LoRA、输出目录、验收、清理（模板 [`templates/run-order.json`](../../templates/run-order.json)）。
2. 探机。HOLD 就等，或换机，并说明换到哪台。
3. 用批量命令渲 1 张 smoke，填 [`templates/smoke-check.md`](../../templates/smoke-check.md)。
4. 算总时长。超过 30 分钟，先报，等我点头。
5. 起队列，每张写成 `render && keep`，各进一个新目录。
6. 要停：杀进程组，列进程，确认一个不剩。
7. 让租约自然到期；我要用卡就立即释放。
8. 登记一个画廊批次，交出链接，读回判决。
9. 按规则 21 到 26 两边清理，再把经验写进单据的 findings。

## 真实案例

- **2026-09-16，画风探针轮。** 拿质量栈探画风（3.5 分钟一张）；停队只杀了叶子，多渲 5 张；同 seed 覆盖废了 48 张里的 30 张。
  代价：Box A 约 40 分钟、补跑 15 分钟、排期拖后约 1 小时，我定性为严重。规则 1 到 11 由此而来。
- **2026-09-01，完整内存释放。** 在 ComfyUI 0.33.1 上把 Box A 卡死。由此有了「只卸模型」的默认值和释放后回读。
- **2026-09-17 与 2026-09-22，每张都释放。** 连发时每张重载，每次 free 再加 1.9 秒。由此有了租约和空闲回收器。
- **2026-10-13，回收站。** 本应可恢复的清理变成了永久删除。由此有了同盘回收目录加还原清单。
- **2026-08-08，从 worktree 起画廊。** 根目录指错，总数崩了，图没丢。由此有了主仓检出守卫。
- **2026-07-20，计划任务重触发。** 九个任务同时触发，训练卡在第 3 步。由此有了「启动后删定义」。

## 试过又放弃的

- 一律先走 Box B（2026-07-18）：改成先探 Box A。
- 每次跑完 POST /free（2026-06-27 到 2026-09-22）：改成租约加回收器。租约 2026-09-17 做好，2026-09-22 定为规则。
- 默认用完整释放：2026-09-01 卡死后放弃；0.42.1 上待复测。
- 远端用回收站：实际是永久删除。
- 用发文件工具或 base64 小部件交付媒体：只有个卡片，或超过大小上限。
