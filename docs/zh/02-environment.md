# 环境：机器、软件栈，什么跑在哪

这页回答：这套方法跑在什么硬件和软件上，哪种活派到哪台机器，agent 又怎么连上这些机器。
数字都是我自己的，带日期。拿它当参照，再按自己的情况填 `templates/fleet.example.yaml`。

> **TL;DR**
> - 四个角色：跑 agent、不出图的 Controller，两台 Windows 渲染机，以及一台不在出图线里的 Linux 节点。
> - Box A 跑质量线和训练。Box B 跑草稿、测试图和数据集，因为它不花钱，也没人在上面打游戏。
> - sidecar ComfyUI 实例只听 Box A 的回环，要在 Box A 本机跑脚本才调得到。
> - 连通性是选路问题：先 LAN，再隧道，全部经受管 wrapper。探活打队列接口，别 ping。
> - Box A 也是我的游戏机。路由、阈值和显存租约都按「我可能正在用 GPU」来设计。

## 机器

| 公开名 | 硬件与角色 |
|---|---|
| Controller | MacBook Air，Apple M5（10 核），24 GB。跑 agent，不出图。 |
| Box A | Windows 台式机，NVIDIA RTX 5080 16 GB，AMD Ryzen 7 9800X3D，内存约 48 GB。质量线和 LoRA 训练的主渲染机。它也是我的游戏机，所以 agent 要给我让路。2026-10-13 起闲置也会睡眠。 |
| Box B | Windows 台式机，NVIDIA RTX 4060 Ti 16 GB，32 GB 内存。跑草稿、测试和数据集的 worker 机。闲置会睡眠。 |
| Linux 节点 | 一对 NVIDIA DGX Spark（头节点加一个工作节点），跑批处理作业和模型服务。不在这里讲的出图线里。 |

## 各机器的软件栈

只写记录里有的版本，附记录日期。

**Controller（macOS）。**
- Claude Code（主会话和 subagent），herdr 管外部 worker，bd 管任务，portless 给本地服务起带名字的 HTTPS 地址。
- Web 出图应用和图库。生产服务只从主检出目录启动，不从 worktree 启动（见下面 2026-08-08 的案例）。
- 显存回收器在这里跑，是一个脱离会话、被系统服务管理器收养的进程，所以 agent 沙箱杀不掉它。

**Box A（Windows）。**
- ComfyUI 0.42.1，2026-10-20 起；torch 2.10.0+cu130。启动参数：DynamicVRAM 开，`--use-sage-attention`，`--fast fp16_accumulation`，`--reserve-vram 2.5`。
- 以 Windows 服务运行，2026-10-20 改成延迟自动启动。真重启后能不能自启，还没验过。
- 2026-10-13 起它闲置也会睡眠，和 Box B 一样。
- 留着回滚路：0.33.1 的源码和 venv。0.42.1 把 ComfyUI 数据库迁到了 0.33.1 打不开的版本，所以回滚要先拷回备份的数据库。
- kohya sd-scripts 有自己的训练 venv：torch 2.7.0+cu128，accelerate 1.13.0，xformers 0.0.30，bitsandbytes 0.49.2，transformers 4.44.2，diffusers 0.32.2。
- triton 按 venv 分别判：ComfyUI venv 里有 triton 3.8.0（2026-09-16），训练 venv 里没有。
- sidecar 实例，每个钉一个 ComfyUI 版本，只听回环，平时停着：
  - Qwen-Image-2.1，跑在 ComfyUI 0.37.0 上（2026-09-29 批准）。同种子的文生图和编辑，跟 0.42.1 比逐像素相同。
  - FLUX 3 Klein，跑在 ComfyUI 0.41.0 上（2026-10-16 搭好，约 11.7 GB 显存）。
  - 一个编辑模型 sidecar，跑在 ComfyUI master 构建上，2026-10-21 搭好。很新，我自己有一份笔记还写着没部署。
- 坑：有个 sidecar 的 venv 是叠在生产 venv 上的薄层，原地升级生产 venv 会连它一起改掉。

**Box B（Windows）。**
- ComfyUI 0.42.1，2026-10-20 起；torch 2.10.0+cu130；开机由计划任务拉起。手动启动任务后 80.6 s 就绪；开机触发要等下次重启才算验过。前端包比 Box A 旧。
- fp16 accumulation 和 SageAttention 默认开。数字是 0.27.1 上测的（2026-09-30），0.42.1 上没重测：fp16 accumulation 在一个 SDXL 系 checkpoint 上快 1.19 倍，在 Anima 上快 1.05 倍；再叠 SageAttention，按线不同又快 2.7% 到 8.7%。
- triton_windows 3.8.0。另装了一套 kohya 用来训练。
- 闲置会睡眠。它的空闲检查每 5 分钟采样一次，短作业叫不醒它。
- 32 GB 内存加 16 GB 页面文件。有一次训练超出提交上限，报 WinError 1455。
- 连不上 GitHub、Civitai、Hugging Face；pip 走国内镜像（2026-06-21 验过，之后没复查）。
- 留着回滚路：0.27.1 的启动脚本加数据库备份。

**驱动差异。** 两台机器的 NVIDIA 驱动不在同一个分支（2026-09-03 记录）。

**Linux 节点。** 由一个带台账的作业执行器往上派批处理活。它的模型服务在跑时，只收小 CPU 作业，GPU 作业一律拒。

## 什么跑在哪，为什么

| 活 | 在哪 | 为什么 |
|---|---|---|
| 质量线（放大加 detailer）、大号 DiT 模型 | Box A | 显卡大。SDXL 质量栈每张约 100 s（3 次取中位数，2026-09-01），GPU 利用率 99%。 |
| sidecar 线（Qwen-Image、编辑模型） | Box A 回环 | 各要各的 ComfyUI 版本；只听回环，不暴露在 LAN 上。 |
| LoRA 训练 | 先 Box A，Box B 也行 | SDXL LoRA dim16、约 2100 步：Box A 约 25 分钟。dim32、1024、开 gradient checkpointing：Box B 约 2.0 s/it（2820 步约 95 分钟）。一台的估时别套到另一台。 |
| 草稿、测试图、A/B 对照臂 | Box B | 不花钱，没人在上面打游戏。2026-09-30 起，测试图直接排到 Box B，不再逐批问。 |
| 数据集渲染 | Box B | 不花钱。有一次约 420 Buzz 花在 Civitai 上，做的数据集 Box B 本来能免费出。 |
| agent、Web 应用、图库、评审页 | Controller | 它不出图。 |
| 批处理作业、模型服务 | Linux 节点 | 不在出图线里。 |

有些路由由资源钉死，不归策略管：某条线的模型或检测器只在一台机器上有，就只能去那台。两台都符合时，`--box auto` 按下面「跟我共用 GPU」那节的探测来选。

## 连通性

连通性是每次调用时选一条路，不是一个写死的主机名。

1. **先 LAN。** 最快，在家默认走它。
2. **再隧道。** Controller 不在家，或者 LAN 不通时用。
3. **最后 mesh VPN。** 在家很快，一退到中继就很慢。

全部经受管 wrapper：一条命令一个 wrapper，辅助脚本里不许有裸 `ssh` 或 `curl`。Controller 上给每台机器保持一条回环转发，由系统服务管理器守着；后面有个选路器挑 LAN、隧道或 VPN，所以脚本看到的永远是每台机器一个固定的本地端点。sidecar 的调法是经远程 PowerShell 执行器在 Box A 本机跑脚本，让脚本去调它自己的回环。

传输实测（同一个 5.94 MB 文件，2026-09-01）：

| 路径 | 稳态吞吐 | 备注 |
|---|---|---|
| LAN | 48.1 MB/s | 走 LAN 时回环 rtt p50 17.4 ms（2026-09-17） |
| mesh VPN | 约 11.2 MB/s | 只是在家的数；首次拉取 10.06 s，复拉 0.53 s（打洞成本） |
| 隧道 | 约 0.33 MB/s | 只有一个样本，复测超时 |

离家时（2026-09-22）顺序反了过来：mesh VPN 走中继只有 3.7 KB/s，隧道有 461 KB/s。选路顺序于是改成 LAN、隧道、VPN。

探活：两台机器都屏蔽了 ICMP，而且 ComfyUI 挂了 SSH 照样在。要探 ComfyUI 的队列接口。别只看 system-stats 接口：它有一次返回 500，同时队列、prompt、object-info 都是 200。

## 跟我共用 GPU

Box A 是我的游戏机。下面这些规则都是因为这个。

1. **先探 Box A，忙就转 Box B。**
   理由：`--box auto` 取代了 2026-07-18 定的「永远先 Box B」。空闲显存低、队列不空、或者不应答，都算 Box A 忙。
2. **我可能在打游戏时，不用 4 倍模型放大。**
   理由：ESRGAN 这类放大的中间大图会把共享显卡撑爆。改用更高的原生分辨率一趟出完。
3. **模型常驻，由租约和空闲回收器释放显存。**
   理由：我 2026-09-22 定的。每张都释放要多付一次 1.9 s 的远程往返，下一张还得重新加载权重。旧规矩「每次跑完都 POST `/free`」作废。
4. **忙闲阈值按模型常驻时的状态定，不按空卡定。**
   理由：模型常驻后，一个 sidecar 闲着时也只剩约 45% 显存，40% 的阈值就判错了。sidecar 的阈值改成 35%。
5. **把我开着的前台程序算进显存预算。**
   理由：我在 Box A 上常开的程序一直占着约 2.4 GB 显存（实测 2370 到 2493 MiB）。作业执行器的 GPU 就绪阈值在 2026-10-19 经我同意从 2048 MiB 提到 4096 MiB；新阈值只部署在 Box A，Box B 上跑的还是 2048 MiB 的旧版。
6. **任何一个 ComfyUI 实例有排队的活，批处理 GPU 作业就等着。**
   理由：standing rule。GPU 守卫会冻住整个 GPU 作业组，这组作业也不许自己往这些 ComfyUI 实例提交 prompt。
7. **动 Box A 先问；调 Box B 已经预先授权。**
   理由：我 2026-09-30 定的。Box B 上的显存、精度、注意力后端、常驻模型、启动参数，agent 可以自己调；Box A、网络平面、删非测试数据，仍然要我点头。

## 真实案例

- **2026-09-22，悄悄退到隧道。** Controller 拿到的 DHCP 地址跟两台机器不在一个网段，选路器一声不吭退到了隧道。一张 Qwen 图 GPU 只用 8 s，墙钟却过了 230 s。网络只有我能修；修好后刷新一次路由就回到 LAN。规则：先查路由缓存，再给回环请求计时。
- **2026-08-28，本来要传 URL 的地方传了机器别名。** 请求辅助函数拿到的是别名而不是解析后的 URL，拼出一个假主机名，被访问代理回了 403。为此白派了一轮网络专家。规则：请求辅助函数只收解析后的完整 URL；那里出 403 是调用写错了。
- **2026-09-17，一份交接把转发读错了。** 云端会话写的交接以为回环转发走的是隧道，提议覆盖它的定义，真照做会把选路器删掉。规则：对路由下判断之前，先读正在跑的那份定义。
- **在沙箱里跑选路探针。** agent 沙箱里所有探针都报 DOWN，还会把结果写进路由缓存。规则：别在沙箱里跑路由状态或刷新；转发卡住就杀掉它的进程，让守护进程重新探。
- **2026-08-08，从 worktree 起生产服务。** 从 worktree 启动后，图库指向一棵稀疏的树，总数从几百掉到个位数。图没丢。规则：生产服务只从主检出目录启动；启动脚本现在会拒绝 worktree 路径。

## 试过又放弃的

- **「永远先 Box B」**（2026-07-18）。换成先探再路由。
- **mesh VPN 当离家方案。** 2026-09-22 测到中继速度后降到最后一位。
- **在家也一律走隧道的转发。** 我 2026-09-01 定了「LAN 通就走 LAN」，之后换成了选路器。
- **旧版 ComfyUI 时代的启动参数理由**（2026-07-02：不加 `--fast`，不加 `--reserve-vram`）。已过时；现在两台都开 fp16 accumulation 和 SageAttention，Box A 预留 2.5 GB。

## 按你自己的环境改

派任何活之前，先复制 `templates/fleet.example.yaml` 填好。

- [ ] 每台机器按角色命名，不写主机名。标明哪台跑 agent、不出图。
- [ ] 每台记下 GPU、显存、内存、操作系统，以及记录日期。
- [ ] 每个实例记下 ComfyUI 版本、回滚路径、数据库是否迁移过。
- [ ] 标明哪台跟人共用，那个人平时在 GPU 上开着什么。
- [ ] 列出每台能跑哪些线，哪些线因为资源只能去某一台。
- [ ] 用词写出选路顺序（LAN、隧道、VPN）。地址放私有配置，不进注册表。
- [ ] 每台写好探活方式（队列接口），以及模型常驻时的忙闲阈值。
- [ ] 写清每台哪些改动已预先授权，哪些要人点头。
- [ ] 记下每台的出网封锁（模型站、包索引），附检查日期。
