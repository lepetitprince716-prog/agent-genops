# 库存管理

agent 怎么知道有什么、在哪：渲染机上的模型和 LoRA、配方、脚本、输出、冷归档、云端花费、远程作业。
核心是两件事：事实去索引或账本里查，不靠猜；每张图都能追回到是什么把它做出来的。

> **TL;DR**
> - 一份机读模型索引，从 Box A 建，每条记录写明 Box B 上有没有这个文件、叫什么名字。agent 原样传它给的规范名，要更新就重新生成，不手改。LoRA 用语义搜索，有词法兜底。
> - 把 LoRA 或控制权重配给底模之前，先从文件头读 块数和 dtype。配错不会报错。
> - 下载直接落到渲染机，控制机只发命令、轮询状态。
> - 写新脚本前，先读脚本注册表和由它生成的目录。
> - 冷归档进私有桶，前面是免费额度 80% 处 fail closed 的配额闸，没有删除参数。每次云端出图、每个远程作业都在账本里留一行。

## 规则

### 模型和 LoRA

1. **只留一份机读模型索引；用 `refresh` 重新生成，绝不手改。**
   理由：旁边有一份带日期的人读判断表，表头写明它不是第二份索引，机器事实一律回到索引。
   再建一份完整的 LoRA 索引被否了，理由是重复造轮子。
2. **`refresh` 只读、增量；机器连不上就非零退出，保留上一份有效索引。索引过期时 `status` 退出码为 3。**
   理由：连不上的机器绝不能被记成「空库存」。快照用 `(mtime_ns, size)` 指纹判失效，文件变了不用全量重扫也能发现。
   目录过期或缺失会挡住出图。
3. **规范名原样从索引或线上服务的 object info 里拿，绝不凭记忆敲文件名。**
   理由：每条记录带 `canonical_name`，就是加载节点认的那个字符串。2026-07-16 一次瑕疵探针跑到一半中止，
   因为本地索引比机器落后一代。checkpoint 以线上服务的 object info 为准。
4. **LoRA 用语义搜索；嵌入用不了时，在同一份索引上退回词法匹配。**
   理由：有了嵌入，「按意图找 LoRA」才好用（一个小的 sentence-transformers 模型，384 维；按 id 加文档哈希增量重算，
   0.1 秒，全量要 27 秒）。2026-08-23 发现控制机上的嵌入模型只下了一半，模型站又连不上，语义搜索直接报错；
   在同一份索引上做零依赖的词法匹配，按角色名查照样能用。索引本身的构建从来不依赖嵌入。`refresh` 必须用装了嵌入依赖的解释器跑，
   否则状态会是 `partial`（2026-09-22）。
5. **内容分级未知就显示为未知，绝不悄悄归类。**
   理由：仓库主人的决定。自训 LoRA 按设计就是底模「Unknown」、没有模型站元数据，家族匹配会退回用路径里的词判断。别去「修」它。
6. **把 LoRA 或控制权重配给底模之前，先读 safetensors 文件头（块数、参数量、张量 dtype），并在模型卡上记下 `blocks`。**
   理由：Anima 有 28、40、52 三种 块数。28 块的 LoRA 挂到 52 块模型上画出来是乱线，不报错；28 块的控制权重挂到
   40 块模型上会错位，也不报错。2026-09-17 盘点时，Box A 上 166 个 Anima LoRA 没有一个是原生 52 块。重映射之后，
   用「patch 数等于张量数除以 3」核对（那次是 280/280；为 0 说明键名方言不对）。厂商标签也会骗人：模型站上标 FP8 的版本实际是 INT8。
7. **默认值从注册表的角色字段解析，不在脚本里写死名字。**
   理由：2026-09 有三处各自定义的默认底模。现在模型卡上有角色（比如 `quality_default`）、能跑的机器、每台机的加载名，
   还有 `no_gain` 这类状态。
8. **下载什么看仓库的文件列表；安装前用模型站 LFS 的对象 id 核对 sha256。**
   理由：有张模型卡介绍了一整套混合精度文件，仓库里一个都没有。社区自定义节点按 commit 钉死。

### 下载

9. **模型直接下到渲染机；控制机只发一句「下载模型 X」再轮询。**
   理由：文件字节从不经过控制机和它那条链路。我这套环境里，Box A 上按需起一个开源的 ComfyUI LoRA 管理器，独立端口，
   跟出图用的 ComfyUI 隔开（不抢显存）。2026-07-12 用一个 6.5 GB 的 checkpoint 端到端验证过，含 sha256。
   模型站的 key 留在机器自己的设置里，从不回显。停掉管理器时隧道一起关。
10. **目标根目录要显式钉死。**
    理由：管理器的默认路径模式会忽略传进去的根目录，按底模归到它自己的默认根下。Box A 有两个 LoRA 根，
    认哪个对，就去找一个已知文件在哪。
11. **每次下载完都重建索引（和嵌入）。**
    理由：索引不知道的新文件，选择时就看不见（2026-06-24 端到端验证：508 条变 509 条，新 LoRA 能被搜到）。
    aria2 后端的完成信号是它的控制文件消失。
12. **觉得某台机缺某个功能时，先查那台机上的工具副本是哪个版本。**
    理由：2026-08-25 一台机上的配方采集扩展落后了两个版本。

### 配方

13. **配方分两层：机器上的配方店是素材层，本地库是管理层，带来源、血缘和使用记录。**
    理由：机器上存的东西，不管是浏览器扩展存的还是手动加的，都在同一个店里；本地库补上店里没有的部分。
    来源是导入时抓下的模型站原始页面数据；血缘记父配方；使用记录列出用过它的作业。追溯链是图到作业到 brief
    到配方到父配方到原始出处。
14. **把配方转成出图 brief 没有副作用；先看 brief，再跑。**
    理由：转换时步数、CFG、分辨率会钳到引擎允许的范围，配方自带的负面词是追加而不是覆盖，额外 LoRA 最多 4 个，
    缺的 LoRA 只警告、不猜替代品。从配方店删东西要我明确确认。

### 脚本

15. **写任何新东西之前，先读脚本注册表和由它生成的目录。**
    理由：2026-06-25 起仓库主人的决定。注册表是一个 JSON，给每个脚本记状态、区域、副作用、目标、默认模式、闸门、超时、
    输出根、清理方式、测试和权威文档。CI 会拒绝没注册的脚本，也拒绝没声明的风险上升。状态（active、probe、legacy、
    test、reference）只看注册表，不看文件名，也不看文件多旧。agent 的查找顺序：路由的 `--list`，然后目录，然后配套文档。
16. **借脚本就复制一份；要改正式脚本，注册表条目、目录行和测试一起改。**
    理由：正式脚本的 CLI、路径和输出行为是别的代码依赖的契约。

### 输出

17. **输出按「驱动模型」归档，旁边的 元数据 JSON 只记真正用过的值。**
    理由：我 2026-06-23 定的规矩。目录名说明是哪个 agent 驱动了这次运行；sidecar 记实际的引擎、底模、LoRA 和强度、
    prompt、seed，绝不填猜的值。PNG 里还嵌着完整的 ComfyUI graph。
18. **分析结果时，读实际提交的那个 graph，不读源码默认值，也不读元数据 JSON。**
    理由：2026-06-25 一次 txt2img 误传了 denoise 0.5，「烘焙 VAE 发灰」「底模过曝」两条结论都是这个 bug 造成的，后来撤回。
19. **在 worktree 里跑的工具，输出根指向主仓检出；worktree 的产出用 `rsync --ignore-existing` 合回去。**
    理由：不这样，账本会分叉，判过的批次在主仓的评审服务里也看不见。绝不为了「合并」去主仓输出树里 `rm`。
20. **归档集是精选的画廊目录。正在用的工作目录不整棵归档，缓存永远不是归档来源。**
    理由：工作目录变动频繁，还夹着测试材料；缓存会自己重建。转码用的暂存目录也不归档。

### 冷归档

21. **配额闸写在上传侧：到免费额度的 80% 就 fail closed，读不到用量也拒绝。**
    理由：Cloudflare 只有预算告警，没有硬断闸，R2 又是后付费，「我没充值」挡不住扣费。免费额度是十进制的 10 GB，
    上限取 8,000,000,000 字节。传输量来自一次 dry-run 同步，所以重推已上传的前缀不花钱，也不会被拒。2026-08-13 定。
22. **没有删除参数，桶是私有的，凭据由我自己在控制台建。**
    理由：常设约束。agent 从不经手明文密钥，脚本从标准环境变量读凭据，不写日志。凭据还不存在时，脚本暂存完就以退出码 2 结束，
    不碰网络。前缀在任何文件系统操作之前先做路径穿越校验。
23. **上传前先转成 WebP q90 并暂存；每批新图落地后从主仓检出推上去，不等人提醒。**
    理由：12 张真实产物实测，PNG 转 WebP，q95 缩 7.1 倍，q90 缩 10.5 倍，q85 缩 13.6 倍。全部 4479 张按 q90 约 1.0 GB，
    占免费额度的 10%。每个顶层目录一个前缀。判为 `no_gain` 的模型，它的出图归档后删掉本地 PNG。
    （2026-08-13 的记忆写的是上传卡在凭据上；现行项目规则把推送当作日常操作。凭据现状这里没有复核。）

### 账本

24. **每次云端出图都是账本里的一行；先报价，在客户端比对预算，超了 fail closed。**
    理由：Civitai 对 API key 没有服务端额度上限。2026-09-30 起用常设预算代替逐张确认：单次 30 Buzz、每个本地日历日 150 Buzz，
    每张追加进一个 JSONL 账本。超上限、批量探针、视频，仍要我批准。
25. **任何花钱的命令之前，先搜账本、数输出目录里的文件；默认带续跑参数；跑完核对账本行数 = 渲染文件数 = spec 条数。**
    理由：2026-09-05 一次付费双跑白花了 257 Buzz（经过见[服务分工](09-providers.md#真实案例)）。贴进对话的花钱命令，要当作可能已经跑过。
26. **NovelAI 用本地清单加每日 Anlas 账本，因为它的 API 不保留历史。**
    理由：账本默认上限每天 300 Anlas，不随手调高；客户端锁在免费档，除非明确标记付费；HTTP 402 就停，不重试。
    2026-09-30 发现本地估价器把付费图算便宜了（1536x1024、23 步，估 8 Anlas，实收 39）。另外，2026-09-01 账本上「已用 638」，大部分其实是记成付费的免费图。
27. **每个远程作业从打包起就在账本里有一条，直到标记为已清理。**
    理由：一个带账本的作业执行器在打包时打出作业 id 和 sha256；查「待清理」能列出打了包还没清的作业。失败或超时的作业
    从不自动删：先看日志，再显式清理。作业前后各做一次文件系统审计，标出作业根目录以外新出现的路径；可疑项按确切路径删，
    并在账本里记一笔。远端作业目录先移进回收目录。

## 流程：给作业找模型

1. 查索引新鲜度（`status`）。退出码 3 就跑 `refresh`。
2. `lookup "<意图>" --kind lora --base <家族>`，读 `canonical_name`、触发词、推荐强度、分级。
3. 核对底模和 LoRA 的 块数。不一致就重映射，再核 patch 数。
4. 把 `canonical_name` 原样贴进出图 brief。

## 流程：归档一批图

1. `status` 读桶用量。读不到就停。
2. `plan`，或不带 `--apply` 的 `push`，看转码结果和传输量。
3. 确认预计总量在上限以内，再 `push --apply`。
4. 绝不传删除参数。绝不归档缓存和工作目录。

## 检查单：写新脚本之前

- [ ] 在注册表和目录里搜过有没有干同样活的脚本。
- [ ] 读过最接近那个的配套文档。
- [ ] 定了：原样复用、复制后改，还是新写。
- [ ] 要新写：注册表条目、目录行、测试、默认模式（只出计划还是直接执行）放在同一个 commit。

## 真实案例

- **2026-07-16，索引过期。** 瑕疵探针跑到一半，机器上已经没有它要的名字。由此有了「规范名从索引或线上 object info 拿」。
- **2026-08-23，控制机嵌入坏了。** 语义搜索挂掉，同一份索引上的词法匹配接着用。由此有了词法兜底。
- **2026-09-17，52 块乱线。** 没重映射的 28 块 LoRA 挂到 52 块底模上，出噪声不报错。由此有了读文件头和 patch 数核对。
- **2026-08-13，归档配额。** 服务商没有硬断闸。由此有了上传侧 80% 的闸门。

## 试过又放弃的

- 在目录旁再建一份完整 LoRA 索引：重复，否决。
- 旧的 Civitai 客户端把 API token 放在命令行参数里，进程列表里看得见：换成经文件描述符传 token 的新客户端。
- 只靠语义搜索找 LoRA：保留，但不再是唯一的路。
