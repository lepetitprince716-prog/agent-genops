# 性能：怎么量、怎么选提速方案

这页回答：怎么判断一个提速是真的，出图时间到底花在哪，以及在 16 GB 消费级显卡上，
哪些量化和蒸馏方案经住了检验。每个数字都带日期、机器和 ComfyUI 版本。
0.27.1 或 0.33.1 上量的数没在 0.42.1 上重测，两台出图机 2026-10-20 起都是 0.42.1。

> **TL;DR**
> - 先量再调。质量线上所有直觉答案（网络、加载模型、轮询）都错了，真正烧时间的是 detailer 重复采样。
> - A/B 按 A-B-A 跑，带显式关闭臂，热态，至少 3 个 seed，取中位数。有条 SDXL 管线跨 seed 方差 24%，单样本 A/B 分辨不了 20% 左右以下的差异。
> - 先换最大的那块，再重新评估剩下的。借来的数字只是假设。
> - 采纳：mxfp8 权重 + INT8 注意力（Anima 3.8B 快 2.11 倍，画质完好）。塌了：无校准 nvfp4。否掉：Box B 上的 fp8 矩阵乘、一个视频少步蒸馏。
> - 质量档由我判，不由 agent 判。来自权重格式和内核的提速做不成 LoRA。

## 规则

1. **动手之前先量时间花在哪。**
   理由：Box A 的 SDXL 质量线（2026-09-01，ComfyUI 0.33.1 时期，1024x1536 放大到 2048x3072）
   GPU 利用率 99%，显存带宽利用率 29–35%，零降频，功耗 329–337 W，上限 385 W。一张图跑四次采样：
   32 步主采样、2 倍模型放大、在 1833x1814 的 crop 上跑 face detailer（差不多重画一整张）、两次 eye
   detailer。检测只要 9.0 ms 和 4.4 ms，VAE 0.6–0.8 秒。杠杆是 detailer 的 crop 尺寸，不是网络，
   也不是加载模型。

2. **profile 只统计真实的设备内核。**
   理由：把框架包装层的算子也算进去，同一份工作会算两遍，总和翻倍。

3. **这些模型不手写内核。**
   理由：GEMM 占 GPU 时间 52–68%，只有降精度能动它，手写内核赢不了厂商库。能融合的部分
   （逐元素、norm、rope、其他）SDXL 约 14%、Anima DiT 约 10%，折算端到端约 5%。
   大家常引用的「注意力占 40–70%」来自视频和 FLUX 类模型，对这里两条线都不成立。

4. **计时用热态，至少重复 3 次，报中位数，丢掉冷启动那次。**
   理由：同一个 SDXL 配方跨 seed 差 24%（81.36–100.73 秒）。有条「阶段提速 19.4%」（109.8→88.55 秒）
   是单样本对单样本，落在这个区间里。一个预蒸馏 checkpoint 最早记的是 3.8 秒，2026-09-30 重测是
   2.1 秒，旧数已删。一次性调用的计时含 Triton 预热，别拿来和常驻 worker 比。

5. **方差按管线自己量，不借。**
   理由：那 24% 来自 detailer 的 crop 尺寸随 seed 变。Qwen-Image 裸采样只有约 1%。

6. **每个开关都测显式关掉的那一档。**
   理由：只测「开」和「不设」，分不清「没用」和「默认已开」。有个缓存节点开和不设一样，
   加测关闭档才证明根本没有可缓存的东西。

7. **同一台机器、同一个时段内交替跑各臂：A-B-A 或 ABBA。**
   理由：常设方法。Box B 的杠杆测试（2026-09-30）全部按 A-B-A 或 ABBA 跑，Box A 上 mxfp8 换进生产
   那次也是同时段交替。

8. **先换最大的那块，再重新量剩下的。**
   理由：把 GGUF Q8_0 的反量化换成真正的 W8A8 int8 convrot 内核，Qwen-Image 2.1 每步从 0.657 秒
   降到 0.210 秒。INT8 注意力后端在 GGUF 底座上只值 5–7%，换完之后值 14–21%（Box A，0.37.0 sidecar，
   2026-09-21）。顺序反了，就会低估后面每个杠杆。

9. **借来的数字连边界一起搬，跨模型只当假设。**
   理由：mxfp8 + INT8 注意力这套组合在 Anima 3.8B 上快 2.11 倍，注意力单独贡献 1.30 倍；
   同一个注意力后端到了 Qwen-Image 的 GGUF 底座上只有 5–7%。

10. **判量化看画质守没守住，不看同 seed 能不能复现同一张图。**
    理由：扩散模型对权重扰动是混沌的。mxfp8 对 bf16 构图和姿势不变，平均像素差 11–19，
    饰品、霓虹字形这类小件会漂。

11. **质量档由我判，agent 只报技术性崩坏。**
    理由：Qwen-Image 上 agent 判 8 步够用，我判 16 步是下限，所有基于 agent 判断的回本测算直接翻倍。
    技术性崩坏指文字乱码、结构塌、欠去噪。

12. **模型常驻，换模型或用完才卸。**
    理由：「每次出图后 POST /free」的旧规则 2026-09-22 起作废。一次 free 要付 1.9 秒远程往返，
    还真会把权重卸掉。Box B（0.27.1）上去掉每刀 free，WAI 每刀省 1.34 秒（11%），Anima 每刀省
    0.35 秒（1%），算不上提速杠杆。现在由意图路由器租用显存，空闲回收器负责释放。

13. **量化元数据烤进 checkpoint，并核实走的是原生路径。**
    理由：加载器的 dtype 下拉只有 fp8 几档，nvfp4 和 mxfp8 要靠文件里逐层的元数据。看服务日志确认识别出
    混精度、走原生算子（不是模拟）。注意力参数要在任何模型导入之前设，因为注意力函数在导入时就绑定了；
    打印绑定函数的名字来核实。

## 时间花在哪

Box A，RTX 5080，torch profiler，只计设备内核，2026-09-16，ComfyUI 0.33.1。

| 桶 | SDXL UNet（fp16，batch 2，1024x1536，230 ms/步） | Anima 2.9B DiT（bf16，batch 1，1024x1024，260 ms/步） |
|---|---|---|
| GEMM | 51.8% | 68.1% |
| 卷积 | 20.2% | 0% |
| 注意力 | 14.0% | 21.6% |
| 逐元素 | 8.9% | 5.9% |
| norm / rope | 3.3% | 3.4% |
| 其他 | 1.8% | 0.9% |

Anima 3.8B（52 块，bf16，CFG batch 2）：1024x1024 每步 659 ms（峰值 7.44 GiB），1024x1536 每步
1099 ms（7.63 GiB）。分辨率越高注意力占比越大，从 21.0% 涨到 26.8%。

单独测 GEMM，形状 4096x2048x2048，随机数据，朴素逐张量缩放（误差是上界，不能当画质结论）：
bf16 0.312 ms；fp8 0.153 ms（2.04 倍，相对误差 0.038）；nvfp4 0.071 ms（4.38 倍，相对误差 0.134）。

## A/B 流程

1. 写下问题和唯一的变量，填 `../../templates/ab-test.md`。
2. 别的全部固定：机器、提示词、分辨率、采样器、步数、LoRA 组合。
3. 臂：对照、处理，开关类再加一个显式关闭臂。LoRA 对照臂用强度 0.001，绝不用 0。
4. seed 至少 3 个，各臂用同一组。
5. 每个臂先暖机一次，这次不计。
6. 同一时段内按 A-B-A（或 ABBA）跑。单张采样时间和墙钟时间分开记。
7. 报中位数和离散范围。差异落在实测的 seed 方差以内，结论就写「分辨不出」。
8. 画质：先比像素差和构图，再把图放到我面前。质量档以我的判断为准。
9. 数字旁边写上日期、机器、ComfyUI 版本、torch 版本、启动参数。

## 量化结论

Anima 3.8B，Box A，30 步，CFG 4.5，1024x1536，同 seed，进程内 worker 跑在 ComfyUI 0.33.1 的库上，
2026-09-16/17。

| 配置 | 采样 | 对 bf16 | 权重 | 画质 |
|---|---|---|---|---|
| bf16 | 34.006 s | 1.00x | 6.99 GiB | 基准 |
| nvfp4（W4A4） | 20.624 s | 1.65x | 2.61 GiB | 塌：线稿丢失、条纹噪点、角色漂移 |
| mxfp8（W8A8） | 20.855 s | 1.63x | 4.04 GiB | 完好 |
| mxfp8 + INT8 注意力 | 16.091 s | 2.11x | 4.04 GiB | 完好，采纳 |

- nvfp4 塌掉的原因：ComfyUI 的 nvfp4 连激活也压到 4 位，而且没有校准。4 位权重扛得住，
  没校准的 4 位激活扛不住。
- nvfp4 并不比 mxfp8 快：每次前向都要对激活做 abs/amax 再打包，省下的又吃回去了。
  这条线卡在这笔开销上，不卡权重带宽。
- 真要再压：走带低秩补偿的 SVD-quant W4A4，或者把最敏感的首尾块留在高精度。这条线不再用无校准 nvfp4。
- mxfp8 只在 Blackwell（RTX 50）上真提速，别的卡会静默反量化（来自厂商文档，没核源码）。
- 重映射后的 LoRA 挂在 mxfp8 模型上没有额外开销：16.295 秒，不挂 16.271 秒。

预蒸馏 Anima 2.9B 换成 mxfp8 放进生产服务（Box A，0.33.1，2026-09-30，同时段交替）：8 步 1.6 秒对
bf16 的 2.1 秒，30 步 11.3 秒对 14.5 秒，快 22–24%。2026-10-01 我放行。放进常驻 worker 再加 INT8 注意力
和融合内核：30 步采样 6.42 秒，8 步 0.88 秒。

Box B 杠杆（RTX 4060 Ti，PyTorch 2.10.0+cu130，ComfyUI 0.27.1，2026-09-30，A-B-A / ABBA）：

| 杠杆 | 结果 | 状态 |
|---|---|---|
| `--fast fp16_accumulation` | WAI 1.19 倍（12.12→10.19 秒），Anima 1.05 倍；构图不变，细节漂移 | 默认开 |
| 再叠 SageAttention | Anima 快线 1.087 倍（4.83→4.45 秒），质量线 1.077 倍，WAI 1.027 倍 | 默认开 |
| fp8 权重 + fp8 矩阵乘 | Anima 反而慢 4%（4.58 对 4.42 秒），PSNR 16.3 dB，构图变了 | 死路 |
| 去掉每刀 `/free` | WAI 1.34 秒（11%），Anima 0.35 秒（1%） | 不是杠杆 |

`--fast fp16_accumulation` 要写全：只写 `--fast` 会打开全部实验性优化。注意力参数互斥，一个进程只能选一个后端。

## 蒸馏与步数结论

- **预蒸馏 Anima 2.9B，8 步，CFG 1：** 热态 2.1 秒，30 步 CFG 4 是 14.2 秒（Box A，0.33.1，896x1152，
  2026-09-30）。快线采纳；之后两台推荐的快线换成了一个 28 块合并底模，挂下面那条 turbo LoRA。CFG 1 时负面提示词不起作用；CFG 大于 1 要跑两遍前向，贵 40–60%。
- **底模挂 turbo LoRA 0.9，10 步：** 热态约 2.5 秒，冷启动约 7 秒。已经蒸馏过的模型别再叠 turbo LoRA。
- **Qwen-Image 2.1 步数档**（Box A，0.37.0 sidecar，2026-09-21；0.42.1 上逐像素相同）：1024x1024 16 步
  4.04 秒、30 步 7.58 秒；2048x2048 16 步 21.45 秒；768x768 2.53 秒。成本跟像素数走，2K 超线性。
  我定 16 步为档。这个模型的少步蒸馏和自烤 mxfp8 按回本测算不做。
- **某视频模型的少步蒸馏 LoRA（8 步）：** 总耗时 30.9 秒对 46.3 秒，只快约 1.5 倍，因为挂上 LoRA 后每步
  反而变慢（2.62 对 1.81 秒）。运动能量从 0.47 掉到 0.30，画面走走停停；音频 −56 对 −45 dB。
  2026-10-21 否掉。单 seed、单提示词，运行时 ComfyUI 0.30.0。

## 做不成 LoRA 的提速

LoRA 装的是权重增量。3.8B 的提速来自权重格式（mxfp8）、一个注意力后端参数、融合内核和常驻进程，
没有一样是权重数值。能发布的形式是一个 mxfp8 checkpoint，说明里写实测阶梯和启动参数。
唯一 LoRA 形态的提速是减步数的 turbo LoRA。

## 真实案例

- **2026-09-01，质量线「慢」。** 先怪网络、加载、轮询。服务日志显示一张图四次采样，外加一次差不多全画幅的
  face detailer。规则：先 profile。
- **2026-09-03，训练的梯度检查点。** 「显存只用了 40%」让人以为能关掉它。结果显存 16380 MiB 用到 15899，
  功耗掉到 53 W，慢约 9 倍（Box B）。规则：开着检查点时的显存峰值，预测不了关掉之后的峰值。
- **2026-09-17，nvfp4。** 技术上全部成立（520 层识别为原生 nvfp4，卡上权重 6984 MB→2671 MB，快 1.65 倍），
  画面塌了。顺带暴露一个真 bug：量化后的 DiT 没法部分卸载，VAE 解码 OOM；解码前显式卸载修好。
- **2026-09-21，8 步对 16 步。** 我推翻了 agent 的「8 步够了」，回本测算翻倍。

## 试过放弃的

- 手写内核（实测天花板约端到端 5%）。
- 无校准 nvfp4 W4A4。
- Box B 上的 fp8 矩阵乘：Anima 的 MLP 输入是 5 维张量，fp8 路径静默回退，输入转换又吃掉了矩阵乘 13% 的收益。
- 把去掉每刀 `/free` 当提速杠杆。
- Box B 上 LoRA 训练的四个杠杆（2026-09-03）：关梯度检查点、batch 2（慢 9.5%）、compile（没生效：
  LoRA 靠 forward monkey-patch 注入，图在每个注入点断开）、换完整 AdamW（稳态一样）。
  1024 px 下 2.9–3.0 s/it 就是这块卡的水平。
- 两台 Windows 机分布式训练：没有 NCCL，链路 2.5 GbE。
- Qwen-Image 文生图上的缓存节点：无效。
